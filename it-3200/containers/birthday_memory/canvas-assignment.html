🎂 Birthday Memory: Build It, Run It, Containerize It

A hands-on assignment where you stand up a full-stack app locally, then package the entire stack — frontend, backend, and database — with Docker Compose.

⏱ Est. time: 3–4 hours 📶 Difficulty: Intermediate 🧩 Individual assignment

📋 Overview

You will work with Birthday Memory, a small full-stack app (React + Vite frontend, Node/Express backend, PostgreSQL database) that stores birthdays and shows them on a searchable calendar. The starter project already runs locally with npm, and already ships a Docker Compose file that containerizes just the database.

Your job has two parts:

  1. Get the app running locally the normal way (Node + the bundled database container) so you understand what it does.
  2. Extend the project so the entire application — frontend, backend, and database — starts with a single docker compose up command.

Read the project's own README before you start — it has the authoritative setup steps this assignment builds on:

Birthday Memory project & README on GitHub (opens in a new tab)

🎯 Learning Objectives

By the end of this assignment, you will be able to:

  • Install and verify a Node.js + PostgreSQL development toolchain on your own machine.
  • Run a multi-service application (client, API, database) locally and diagnose connection issues between them.
  • Write a Dockerfile for a Node.js backend and for a Vite-based frontend.
  • Extend a docker-compose.yml file to orchestrate multiple containers on a shared network.
  • Explain the difference between host-mapped ports and container-internal ports when services talk to each other inside Docker.

🚀 Part 1 — Run the App Locally

Follow these steps exactly once to confirm the app works before you touch Docker Compose.

1. Clone and install

git clone https://github.com/hvaandres/cyber-uvu-student-projects.git
cd cyber-uvu-student-projects/it-3200/containers/birthday_memory
npm run install:all

2. Configure the database connection

cp server/.env.example server/.env

The defaults already match the bundled Docker database, so leave the file as-is for now.

3. Start PostgreSQL with the existing Docker Compose file

npm run db:up
docker compose ps   # confirm the "thebirthdates-db" service is healthy

4. (Optional) Seed sample data

npm --prefix server run seed

5. Start the app

npm run dev

Open http://localhost:5173 in your browser. Add a birthday, search for it, and check the calendar view before moving on. Press Ctrl+C to stop the app when you're done exploring.

🐳 Part 2 — Containerize the Whole App

This is the core of the assignment. Right now, docker-compose.yml only defines the postgres service. You will add two more services — backend and frontend — so that docker compose up --build launches all three containers together, networked so they can talk to each other.

Step A — Write a Dockerfile for the backend

Create server/Dockerfile. It needs to:

  • Start from a Node 18+ base image (e.g. node:18-alpine).
  • Copy package.json/package-lock.json first and run npm ci (better layer caching than copying everything at once).
  • Copy the rest of the server/ source.
  • Expose the API port (check server/.env.example for the port it listens on).
  • Run the app with its existing start script from server/package.json.

Step B — Write a Dockerfile for the frontend

Create client/Dockerfile. The simplest approach that satisfies this assignment: run Vite's own dev server inside the container (same command you already used in Part 1), bound to 0.0.0.0 so it's reachable from outside the container, and expose port 5173.

Want an extra challenge? (optional, not required for full credit)

Instead of running the Vite dev server, use a multi-stage build: build the static site with vite build in one stage, then copy the output into an nginx:alpine stage to serve it. You'll need an nginx config that proxies /api requests to the backend service.

Step C — Add both services to docker-compose.yml

Keep the existing postgres service untouched, and add backend and frontend alongside it. Things to get right:

  • Each new service needs a build: context pointing at its folder (./server or ./client) instead of an image: line.
  • Map container ports to host ports with ports: (e.g. backend 4000:4000, frontend 5173:5173).
  • Inside the Docker network, services reach each other by service name, not localhost. Your backend's database host must be the Compose service name (e.g. postgres), and the port is the container-internal port 5432 — not the host-mapped 5544 from server/.env. Pass these as environment: values on the backend service rather than relying on the .env file, which is written for running on your host.
  • Use depends_on so the backend waits for postgres, and the frontend waits for the backend.
  • Give the frontend an environment variable pointing at the backend's URL (see VITE_API_TARGET in client/vite.config.js) — inside the network this should reference the backend service name, not localhost.

Step D — Build and run everything

npm run db:down          # stop anything from Part 1 first
docker compose up --build

If it works, one command brought up the database, the API, and the web client — no local npm run dev required.

✅ Part 3 — Verify Everything Works

Confirm each of these before you submit:

  • docker compose ps shows all three services as running/healthy.
  • docker compose logs backend shows the API connected to Postgres with no errors.
  • The site loads in your browser at the frontend's mapped port and the calendar renders.
  • You can add a new birthday through the containerized app and see it appear in search and on the calendar.
  • Stopping and restarting with docker compose down then docker compose up (no --build) still works, and previously added birthdays are still there (the named volume persisted them).

🛠️ Troubleshooting

Click a problem below to expand its fix.

"failed to connect to the Docker daemon"

Docker Desktop isn't running. Open it from your Applications/Start menu and wait for the whale icon to show it's ready, then retry.

Backend container can't reach Postgres (ECONNREFUSED)

Almost always a host/port mix-up. Inside docker-compose.yml, the backend must use the Postgres service name as the host (e.g. postgres) and port 5432 — not localhost and not 5544. Those only work from your host machine, not from inside another container.

"Port is already in use" / EADDRINUSE

Something else is already bound to that port. Stop the Part 1 npm run dev process first (Ctrl+C), and run npm run db:down before starting the full Compose stack.

Frontend loads but API calls fail

Check the frontend's environment variable for the API URL — inside the Docker network it should point at http://backend:4000 (the service name), not http://localhost:4000, since localhost inside a container refers to that container itself.
